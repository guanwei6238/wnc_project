# CLAUDE.md — 安全閘道器專案

## 專案目標

開發一台**安全閘道器（security gateway）**：流量先在本地檢測，本地判斷不出來的才送到雲端做重量級分析。
- 前期原型：**Raspberry Pi 3 Model B+**（之後會換正式設備）
- 需要**兩個網路 port**（內網 / 外網分離）
- OS：Linux-like，目前傾向 Raspberry Pi OS Lite 64-bit（Debian trixie）

---

## 最重要的工作方式規則

**動手之前，必須先跟開發者討論清楚要怎麼做，取得明確同意才開始寫程式或建檔案。**

開發者正在**學習這個領域的技術**，目的不只是把東西做出來，而是要理解到「之後能自己改」的程度。
因此「一次把東西全部做完交出去」對這個專案是**有害的** —— 會產生開發者看不懂、不敢改的程式碼。

### 具體規則

1. **一次只做一步。** 不要因為預期後面會用到，就一次建立整套檔案結構。
   做完一步就停下來，讓開發者確認、動手摸過、問完問題，再進下一步。

2. **動手前先講清楚要做什麼、為什麼這樣做。** 包含：
   - 這一步解決什麼問題
   - 有哪些做法、為什麼選這個（取捨是什麼）
   - 做完之後開發者可以觀察到什麼

3. **開發者問「為什麼」「這是什麼」的時候，那是要學，不是要你補程式碼。**
   用解釋回答，不要直接動手改東西。

4. **解釋要能連回實機。** 在 Docker/容器裡做的任何事，都要說明它在 Pi 上對應到什麼、
   哪些行為等價、哪些不等價。

5. **不確定開發者想要哪個方向就問。** 尤其是會影響後續架構的決定。

6. **不要預先最佳化。** eBPF / XDP / DPDK 都是後期的事，前期先用 nftables + NFQUEUE 把邏輯跑通。

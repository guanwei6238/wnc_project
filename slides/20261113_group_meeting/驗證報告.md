## 要改的

### 1.（中）p12 當場講：「storage 管理有效」講成三個任務都成立
- **位置**：講稿「一、當場講」第 12 頁（`slide_implement.md` §3 p12 的當場講也是同一句）
- **現在**：「加了 flow-level features 之後，黃色和綠色明顯變高；而且完整版，也就是綠色，和 Ideal 很接近，表示 storage 管理有效。」（接在三張子圖一起講）
- **論文**：只有 P2P 這樣說。
  - P2P（p.12 §7.2）："The full version of NetBeacon has comparable performance with the ideal solutions, demonstrating the effectiveness of stateful storage management."
  - Covert channel（p.13 §7.2）："the quantitative benefits of stateful storage management are not significant in this task."
  - DDoS（p.13 §7.2）："We notice that the quantitative benefits of the stateful storage management are not significant in this task."
  - Fig. 13 上 covert channel、DDoS 的黃色（w/o Optimization）和綠色（Full Version）一樣接近 Ideal，所以這兩個任務不能用「綠色接近 Ideal」證明 storage 管理有效。
- **建議**：「三個任務完整版都和 Ideal 很接近。P2P 這個任務，論文說這表示 storage 管理有效；covert channel 和 DDoS，有沒有 storage 管理差不多，論文自己說效益不明顯。」（「二、補充」第 12 頁已經寫對，只要把當場講改成一致）

### 2.（中）p3 當場講與補充：「模型只能是 tree」比論文說得強
- **位置**：講稿「一、當場講」第 3 頁；「二、補充」第 3 頁的小標「為什麼模型只能是 tree」
- **現在**：「這些限制決定了後面所有設計：模型只能是 tree，因為 tree 的結構像 match/action」
- **論文**（p.6 §4.2）："Similar to prior art [26, 51, 63], NetBeacon sticks to decision tree based learning models because their constructions are more similar to the match/action operations on the data plane, compared with the neural networks that involve significant non-linear computations." —— 是「選擇」tree，不是「只能」。
- **建議**：「所以模型選 tree，因為 tree 的結構比 neural network 更像 match/action」；補充的小標改成「為什麼選 tree」。

### 3.（中）p9 當場講與圖：index 只有 long flow 才算，和 Alg. 1 的順序不同
- **位置**：講稿「一、當場講」第 9 頁；投影片 p9 的流程圖（long-short 分類 → index）
- **現在**：「長的，才去算 index：把 5-tuple 做 hash，再除以 register 數取餘數。」圖上 index 節點在 long-short 分類之後。
- **論文**：每個 packet 一進來就先算 index，靠它讀 register 裡存的 flow ID，才知道是不是新 flow；判成 long 之後才是「要不要佔用」。
  - Alg. 1 第 1–2 行（p.10）："H1 ← Hash(P.5t) ▷ Derive flow hash from packet 5-tuple"、"Sid ← H1[IndexSize : 0] ▷ Derive storage index"（在查 flow class table 之前，所有 packet 都做）
  - p.10 §5.3："it retrieves the stored true flow ID (e.g., 5-tuple) using Sid and compares it with P's flow ID."
  - p.10 §5.3："If P is classified as a long-flow packet, NetBeacon checks whether the storage on Sid is empty or is ready to be overwritten."
  - Fig. 3（p.5）的處理順序也是 Get Storage Index 在前。
- **建議**：講稿改成「每個 packet 都會算 index ＝ H(5-tuple) % N，用它找到對應的 register、比對裡面存的 flow ID，才知道是不是新 flow。新 flow 被判成 long，才去看這個 register 能不能佔用」。圖可以不改，但講稿補一句「圖把順序簡化了，index 其實每個 packet 都先算」。

### 4.（中）p9 當場講：long-short 模型「看前 7 個 packet」容易誤解
- **位置**：講稿「一、當場講」第 9 頁（`slide_implement.md` §3 p9 當場講同句）
- **現在**：「long-short 模型在 P2P 任務是看前 7 個 packet，accuracy 82%。」
- **論文**（p.9 §5.2）："a long-short flow binary classification model using only per-packet features to decide whether a packet belongs to a long flow or not. … The first N packets in the long (short) flows are taken as long (short) flow samples. Then per-packet features are used for training and classification. … For instance, N = 7 and the accuracy is 82% in the P2P application fingerprinting task." —— 模型逐 packet 判斷；7 是訓練時每條 flow 取幾個 packet 當樣本，不是要等 7 個 packet 才判斷。
- **建議**：「long-short 模型只看單一 packet 的 features；訓練時取每條 flow 的前 7 個 packet 當樣本，P2P 任務 accuracy 82%。」（「二、補充」第 9 頁已經寫對）

#### 【中】7. 第 5 頁：最下排七步講成每個沒命中的 packet 都會走完

#### 【中】9. 第 10 頁最後一句：「就沒有後面這幾列」和「下一個 packet 再做一次同樣的判斷」互相矛盾，而且推論沒有在當場講標示

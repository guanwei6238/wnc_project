## 二、預期問題

依兩方標的重要程度合併排序。「誰」：公司、老師。

### 1. 沒有 alert 就 trust：本地抓不到的攻擊會不會直接被 trust？（老師；公司）
- 問法：「11/02 偵測率很低，大部分攻擊本來就沒有 alert，這些 connection 不就直接被 trust、之後都不看了？這和上次問的『rule 還是 dataset』有什麼關係？」
- 逐字稿現況：部分。第 6 頁講了「trusted 之後才送的攻擊看不到」，第 13 頁補充講了「scan、flood 要靠 edge AI 和 cloud」；沒講「漏掉的會被 trust」，也沒回到「rule 還是 dataset」。
- 可以回答的事實：
  - auto trust 的條件要**兩個方向**都至少 `min_packets` 個 packet（`setting.example.toml`、`src/agent/trust.rs`）。所以兩類流量永遠不會被 trust：
    - 單向的 scan、flood。
    - 只有 SYN 沒有回應的 connection，例如 Muhstik 的 62 條。
  - 純 SYN 的 scan 一定進 Suricata，trust 對它沒影響（DECISIONS §5「限制」）。
  - 會被 trust 的是「雙向、有來有回、本地 rule 沒看到問題」的 connection。auto trust 只代表本地 rule 沒看到，不代表良性；所以預設關，doctor 一律給 warning（DECISIONS §19）。
  - 這類 connection 之後要怎麼再看，有兩個方向，都**還沒決定**：
    - 「部分檢查」（O20）：Docker 實驗只檢查每段開頭，可以抓到長 connection 後段的攻擊，約送 5–8% 的 packet。固定長度會被「先塞資料再攻擊」繞過，隨機長度抓得到 83–90%（`tests/partial_inspect/README.md`、DECISIONS §20）。
    - 讓 edge AI 吃抽樣資料（decisions.md O19：Suricata 吃不了零散的抽樣 packet，edge AI 可以）。
- 還沒有答案：「rule 還是 dataset」這次沒有新實驗。候選的「rule 覆蓋檢查」「加 event rule 重跑」都還沒做。

### 2. 先裝正常再攻擊（trust-then-attack）（老師；公司）
- 問法：「先送雙向各 10 個 packet、撐過 5 秒，就被 trust 15 分鐘，之後的 exploit 全部走 trusted 的路？」
- 逐字稿現況：部分。承認風險、預設關、doctor 警告；沒有緩解措施和量測。
- 可以回答的事實：
  - 已有的：SYN／FIN／RST 一律進 Suricata，控制 packet 上的 alert 會立刻 revoke。TTL 到期會回到 Suricata，重新觀察（DECISIONS §6、§19）。
  - 規劃中、**還沒決定**：trusted connection 的部分檢查（O20，見第 1 題）。
  - 合成 connection 的實驗（`tests/partial_inspect/README.md` 實驗 5，offline Suricata）：只看前 20 個 packet、之後完全不看時，後段的攻擊 0% 抓到。
- 還沒有答案：門檻是固定、可預測的，沒有設計隨機化；真實流量上這種攻擊**沒有量**。

### 3. UDP 也會被 trust，但 UDP 沒有 SYN／FIN／RST（老師）
- 問法：「trusted 的 UDP 之後完全不看，DNS tunnel、UDP 的 C&C 怎麼辦？」
- 逐字稿現況：沒有。
- 可以回答的事實：
  - 對。UDP 沒有控制 packet 的訊號，只能靠 TTL（DECISIONS §6「UDP 沒有這種訊號，只能靠 TTL」）。
  - 目前的設定沒有「不 trust UDP」的選項：`[trust]` 只有 `auto`、`min_packets`、`min_age`、`ttl`、`check_interval`（`src/config.rs`）。
  - UDP 沒有 TCP 的 window，偽造同一組 5-tuple 的 UDP packet 會共用 trust（**推論**，沒有測）。
- 還沒有答案：要不要限制 UDP 的 trust，**還沒討論**。

### 4. conntrack 也是用 5-tuple 找 entry，偽造 packet 為什麼繞不過？（老師）
- 問法：「偽造同一組 5-tuple 的非 SYN packet 注入 trusted connection，不是一樣享有 trust？」
- 逐字稿現況：部分。有講純 SYN 的情況，沒講 in-window 注入。
- 可以回答的事實：
  - TCP 的 packet 不在 window 內時，conntrack 判成 INVALID，packet 上沒有 conntrack 的 entry，ct mark 比對不到，就會進 Suricata。實際觀察過：Honeypot-5-1 重播時有 packet 搶先經過 conntrack、被判成 INVALID 而進 queue（DECISIONS §6）。
  - 要注入 window 內的 packet，攻擊者得知道序號，也就是在路徑上。這個情況**沒有測**。
  - 用 nft set 存 5-tuple 更弱：connection 結束後，同一組 5-tuple 的新 connection 一樣會被放行（DECISIONS §5）。
  - UDP 見第 3 題。

### 5. 容量換成 Mbps 是多少？放到正式設備呢？（公司；老師）
- 逐字稿現況：部分。有 kpps 和定義，沒有 Mbps、沒有正式設備的推算。
- 可以回答的事實：
  - **小 packet**：容量測試的兩個 pcap，平均 packet 是 60.06 bytes（17-1 (Kenjiro)）和 71.38 bytes（1-1 (Hide and Seek)）（`capinfos`，`~/datasets/throughput/pcaps/S_m17.pcap`、`S_m1.pcap`）。換算（**推算**，以 frame 大小計）：`ids` 50–80 kpps 約 29–38 Mbps，`ips` 60 kpps 約 29–34 Mbps。
  - **大 packet、一條 TCP connection**（iperf3，1,454 bytes）：
    - Pi 開 RPS 時轉送 ≥ 88 kpps（約 1 Gbps）。
    - Suricata（`ids`、full rules）只檢查得了不到 10 kpps（約 116 Mbps）：10 kpps 時那個 worker 已經 100% 忙，漏掉 15%（`tests/cpu_alloc/README.md` 實驗 5）。
    - 一條 connection 只會進一個 worker，開多個 group 也沒用。
    - 這就是 trust 的用途：一條大流量的 connection 被 trust 之後不用 Suricata 看。
  - 鎖 1000 MHz 的原因：這是持續滿載也不降頻的時脈（DECISIONS「共同的量測條件」）。
- 還沒有答案：對到正式設備的推算**沒有做**（硬體還沒定）。

### 6. fail-open：攻擊者能不能故意弄倒 Suricata，打開放行的空窗？（公司；老師）
- 逐字稿現況：部分。有講設計取捨和 log，沒有討論攻擊者主動觸發。
- 可以回答的事實：
  - `when_unavailable = "drop"` 可以改成空窗期丟掉。不管哪一種都記 log（`uninspected_ms`）（DECISIONS §11）。
  - 重啟的退避從 1 秒加倍到 60 秒（DECISIONS §10）。
  - Pi 載入完整 rule 就緒約 38 秒（DECISIONS §16）；實機 demo 時 41 秒（`tests/demo/README.md`）。
  - `accept` 時，exception policy 是 ignore：Suricata 記憶體用完時照常放行（DECISIONS §11）。
- 還沒有答案：
  - 能不能用特定 packet 讓 Suricata 當掉，屬於 Suricata 本身的漏洞，**沒有分析**。
  - 空窗期只記 log，沒有對外告警，**還沒做**。

### 7. `ids` 下攻擊者大量送 packet，讓 Suricata 跟不上（老師）
- 逐字稿現況：部分。
- 可以回答的事實：

  - 頻寬換算見第 5 題。
- 還沒有答案：這種攻擊情境的實驗**沒有做**。

### 8. wnc-gw 自己當掉、被 OOM kill 呢？（公司）
- 逐字稿現況：沒有。
- 可以回答的事實：
  - Suricata 會跟著結束（`PR_SET_PDEATHSIG`，`src/ids/spawned.rs`），不會留下佔著 queue 的 Suricata。
  - wnc-gw 被強制結束時 table 會留著，只有正常停止才移除。流量照 table 裡最後的規則走（**推論**，從程式和 kernel 的行為推，沒有測）：

  - 重新 `run` 時：用 replace 換掉留下的 table（`src/firewall.rs` `install`），並清掉上次留下的 trust（`src/cli/run.rs` `clear_earlier_trust`）。
- 還沒有答案：

### 17. 我們的 SoC 有硬體加速，packet 不經過 netfilter，怎麼共存？（公司）
- 逐字稿現況：沒有。
- 可以回答的事實：
  - flow offload（nft flowtable，軟體或硬體）命中的 packet 不經過後面的 netfilter hook，也不會進 Suricata（`references/platform-backends.md` §3）。
  - 所以全域的 flow offload 不能開：OpenWrt 上不能開 fw4 的全域 flow offloading（SKILL.md §4 第 6 項）。規劃是只讓 trusted connection 走 fast path。flowtable 當 L3 的後端（O5）**還沒決定**。
  - `bridge` 模式下 flowtable 對純橋接的流量沒有作用。Pi 沒有硬體 offload。
  - 09/21 的報告講過「已經有結論的連線才 offload」。

  - Suricata 本身支援不中斷的 live reload（unix socket 的 `reload-rules`、`ruleset-reload-nonblocking`，`references/rules-nft-suricata.md`）。
  - wnc-gw 啟動 Suricata 時已經開了 unix socket（doctor-checks.md）。
  - rule 管線是規劃的第 4 步，**還沒做**。

### 19. eve.json 沒有上限，flash 寫得起嗎？log 怎麼接管理平台？（公司）
- 逐字稿現況：部分。
- 可以回答的事實：
  - wnc-gw 的 log 只印到 stderr，`--log-format json` 給程式讀。
  - Pi OS 的 journald 只存在記憶體；Debian 上用 systemd 的 `LogNamespace` 持久保存，已決定、**還沒做**（DECISIONS §18）。
  - Suricata 的 eve.json 等目前沒有上限，做法**還沒決定**（DECISIONS §20）。Pi 的 demo 把 Suricata 的 log 目錄放在 tmpfs。
- 還沒有答案：寫入量**沒有量**。

### 20. 現在用什麼權限跑？Suricata 被攻陷的影響範圍？（公司）
- 逐字稿現況：部分。
- 可以回答的事實：
  - 現在是單一 process。裝 nft table、寫 ct mark 都要 `CAP_NET_ADMIN`（`src/kernel/conntrack.rs` 的錯誤訊息），實際上是 root。
  - Suricata 由 wnc-gw 啟動，共用帳號和權限，doctor 會警告。
  - 規劃（**建議**，SKILL.md §3 的表；什麼時候拆是 O1，**還沒決定**，做 cloud 迴路之前要再決定一次）：
    - 拆成只有 `CAP_NET_ADMIN`、`CAP_BPF` 的 privd，和無特權的 agent。
    - Suricata 用非 root、開 landlock、關閉 Lua 規則。
- 也可以用同一點回答老師的「手動 `trust add` 誰能用」：要 `CAP_NET_ADMIN`。

### 21. cloud 回 trust 的通道誰保證？上傳什麼？斷線怎麼辦？（公司；老師）
